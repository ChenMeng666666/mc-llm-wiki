# 独立复核与后续盲评依据

本轮没有开放任务的模型输出，因此没有可评分的答案引用或任务成功率；不能用报告的说服力补齐这些指标。下面提供独立复核方式和后续真实任务的盲评规约。

## 当前结论的独立复核

评审者不必接受作者判断，可以使用自己的环境和命令核验：

1. 核对 `protocol.json` hash、ASAR hash、随附 Node 版本及提取包版本；版本不相同则报告可迁移性未知，不替作者补写通过。
2. 对固定上游源码核算 public-lock.json 内容 hash。直接加载 original 变体应复现重复注册；compat 变体只删冗余 provide，dynamic 变体额外把 section 改为 context，不能混为同一版本。
3. 执行 run_probes.mjs，检查 probe-results 的具体布尔结果，不以退出码 0 当作所有记忆契约通过。探针退出码只表示证据采集是否完成。
4. 从原始压缩 trace 独立解压定位报告的 seq/行号；不得上传含认证信息的全文。确认两条安装请求、正确 desktop 命令、ASAR/PATH 错误，以及没有第二个根会话；若发现遗漏的 DSH_HOME 或另一份真实日志，应重新评估数据覆盖。
5. 专门反驳建议：寻找一个明确的跨会话错误及外部验收依据。如果存在，本报告“尚未确认跨会话失败”的适用范围必须修订；不能用合成 fixture 代替该证据。

## 后续真实任务的盲评包

先建立时间边界与 task ID，再由未参与方案调整的人准备每题：原始来源 ID/事件定位、有效时间、项目边界、必要证据、明确未知项、外部结果验证命令。实际任务前冻结该文件及 hash；方案调优不得读取后续任务答案。

同一任务的各基线输出随机标为 A/B/C，评审时隐藏方案名。提供完整输出、允许引用的证据摘录、外部测试结果以及实际 token/延迟/费用记录；不能只提供作者选择的成功片段。

按以下维度分别记录，不合并成未经校准的总分：

- 最终结果：外部 verifier 通过/失败/不可判定；开放任务逐条核对事实，不因文风加分。
- 证据覆盖：预先指定的必要证据是否全部找到，关键反证是否保留。
- 引用支持：每个重要可验证断言的引用是否直接支持，时间/作用域是否正确；有来源 ID 不等于蕴含通过。
- 错误记忆影响：是否采用已替代值、其他项目资料，或把模型推断当成用户决定。
- 拒答：材料确实不足时是否明确未知，而非编造；材料充分时是否不必要拒答。
- 用户纠正：以实际新增纠正事件计数；不把运行时 user/message 通知计入。
- 资源：实际 tokenizer/调用记录，避免把字符数当 token；检索与模型时延分开。

评审分歧必须回到原始依据裁定，保留不可判定。作者和第二个模型意见一致不构成外部真值。第三方重跑属于可复核证据；未实际进行时不能声称独立复现。
