# LLM Wiki：研究依据与架构取舍

调研日期：2026-10-21。定位：个人/小团队在本地文件中长期累积研究知识，并可把可复用经验提炼为技能。这里的“最优”指在可追溯性、正确性、维护成本、上下文开销和可迁移性之间适合该约束的初始选择；没有在用户实际语料上跑检索/问答基准，因此不是全局最优性证明。

## 指定资料的结论

**Karpathy，LLM Wiki。** 采用 immutable raw → 持续维护的 Markdown wiki → schema，以及 ingest/query/lint、内容目录和操作记录。它是架构想法，不是对各种检索系统的对照实验；文中对 RAG“每次重新发现”的描述针对常见实践，不意味着 RAG 不能缓存、增量维护或与 wiki 结合。本实现保留便携文件结构，也允许查询回查原始证据。[原始 gist](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)

**WikiSkill，Tang et al.，2026，arXiv v1。** 核心借鉴是 raw experience → persistent wiki → skills 的分层、增量 patch、候选验证门与回滚；被拒绝的技能不启用，相关经验仍保留。论文实验直接注入 active skills 全文，主动排除召回/触发失败，故不能据此声称某种 top-k 或向量召回最好。论文也承认缺少自动 wiki pruning、严格提升门槛可能错过中性铺垫，并未覆盖超长执行。本 skill 把知识维护与候选激活分开；并未实现论文训练循环或复现其 benchmark。[论文 §3.2、Limitations](https://arxiv.org/html/2608.27454v1)

**rohitg00，LLM Wiki v2。** 采用它对生命周期、supersession、typed relations、来源治理、会话沉淀和按需混合检索的提醒。它是工程经验文，不是每条建议的实证证明。特别修正：访问次数不提高事实真实性；新材料不能自动推翻旧材料；last-write-wins 不适合知识冲突；模型自评不应成为唯一质量门；“100/200 页就上向量库”只可作粗略经验，升级应看覆盖率和预算。[扩展 gist](https://gist.github.com/rohitg00/2067ab416f7bbe447c1977edaaa681e2)

两个 gist 是动态页面，本次阅读未固定 Git revision；未来复核应取得新快照并比较差异，不能假设内容永久不变。没有复制或分发其完整原文。

## 补充的一手研究

下表的“落地选择”是本方案从论文得到的工程推断，不是论文对本 skill 的验证。仅 WikiSkill 及其明确相关段落做了方法级全文核读；下表以论文摘要、公开方法说明/相关段落做定向核验，不宣称逐篇全面复现。

| 研究 | 与本任务有关的结果/方法 | 落地选择与边界 |
|---|---|---|
| [ACE: Agentic Context Engineering，2510.04618](https://arxiv.org/abs/2510.04618) | 把上下文视作持续演化的 playbook，通过生成、反思、整理和结构化增量更新，缓解反复重写造成的信息丢失 | 小 patch、保留细节出处；角色可以是同一 agent 的阶段，不要求三个常驻 agent。没有照搬其基准提升数字 |
| [A-MEM，2502.12110](https://arxiv.org/abs/2502.12110) | 用结构化笔记、动态链接和记忆更新组织经验 | 页面稳定 ID、别名、来源和显式关联；关联是导航线索，仍需边的证据，不能把相似度当因果 |
| [GraphRAG: From Local to Global，2404.16130](https://arxiv.org/abs/2404.16130) | 通过实体图与预生成 community summaries 处理语料级综合问题 | 全局问题要跨主题覆盖；大规模语料可评估层级综述。原研究特定全局任务的收益不能外推为所有事实查询都需要图数据库 |
| [HippoRAG 2: From RAG to Memory，2502.14802](https://arxiv.org/abs/2502.14802) | 结合 passage 与图检索改进事实、综合及关联任务，提醒结构化检索也需守住基本事实召回 | 同时保留直接文本路径，不能仅靠抽取图边。此版没有实现 PageRank 或复现其系统 |
| [Zep，2501.13956](https://arxiv.org/abs/2501.13956) | 时间感知的动态知识图保留关系历史，处理持续更新的对话与业务数据 | 分开事实有效时间和记录时间，明确 supersession；这是轻量字段设计，不是声称复刻 Graphiti 或其性能 |
| [Self-RAG，2310.11511](https://arxiv.org/abs/2310.11511) | 训练模型按需检索并评议证据/生成，固定数量无差别检索并非总有效 | 查询按缺口扩展、检查支持度，避免无依据回答。本 skill 的提示流程借鉴不等同其训练出的 reflection tokens，也不能继承其指标 |
| [ALCE: Enabling LLMs to Generate Text with Citations，EMNLP 2023](https://aclanthology.org/2023.emnlp-main.398/) | 把事实正确性和引用质量拆开评估；有引用不保证引用充分或正确 | 检查 claim-level citation precision/coverage，不能只 lint “存在链接” |
| [LongMemEval，2410.10813](https://arxiv.org/abs/2410.10813) | 测信息抽取、跨会话推理、时间、知识更新和拒答，区分索引/检索/阅读 | 这五类是本地评测的基本覆盖面；长上下文并不自动解决长期知识更新 |
| [LongMemEval-V2，2605.12493，WIP](https://arxiv.org/abs/2605.12493) | 面向环境经验，评状态、动态变化、流程、易错点及前提意识；agent 文件取证有效但延迟较高 | 保留 trace 文件按需读取；效率和效果都测，不能只比较回答准确率。WIP 结论保留阶段性标识 |
| [Trace2Skill，Ni et al.，2603.25158](https://arxiv.org/abs/2603.25158) | 汇总多条执行轨迹中的局部教训再归纳可迁移技能，避免顺序追逐单例 | 从正反例找条件，再写候选；不强制昂贵的并行 fleet。注意另有同名 EDA 论文 2605.21810，本行指前者 |
| [EvoSkill，2603.02766](https://arxiv.org/abs/2603.02766) | 失败分析产生技能变更，利用 held-out 表现选择并考虑质量/成本的 Pareto 取舍 | 候选与 active 版本分离，质量、时延、费用分开记录；本地少量 smoke test 不等价其 benchmark |
| [SkillOpt，2605.23904](https://arxiv.org/abs/2605.23904) | 固定模型，把技能视作外部可优化状态，以有限文本改动和独立验证控制演化 | 小范围改动、记录拒绝尝试、固定门槛与评测预算；不把自评当奖励真值，不开启无界自动优化 |

这些研究使用不同模型、数据集、任务与验证器。不能把它们报告的提升相加，也不能根据各自最高分给本实现写一个预计准确率。

## 对所给“生产级 Skill Engine”伪代码的评估

它描述的是**可调用代码插件的发现与执行引擎**；本请求需要的是**指导 agent 持续编译知识的技能包**。两者可以集成，但不必为使用一个 wiki skill 实现另一层动态 Python 插件系统。

| 建议 | 取舍 |
|---|---|
| 加载 → 召回 → 执行分离 | 保留概念边界；本技能由宿主发现，文件工具只执行确定性知识库操作 |
| 统一返回、错误记录、缓存 | 工具采用稳定 JSON 状态码与事务记录。小型本地库直接扫描，避免缓存过期影响正确性 |
| `skill.json`、入口白名单 | 对插件接口有用；Skill 包入口是 SKILL.md。白名单只约束选函数，import 的顶层代码仍可执行任意动作 |
| `inspect.signature` 过滤参数 | 它只能匹配调用形状，不能授权、验证类型或阻止危险值；静默丢字段还会隐藏错误。CLI/manifest 对未知字段拒绝并验证具体路径/值 |
| `permissions` 声明 | 属元数据，不会自动限制文件或网络；需要宿主/OS 真正执行授权 |
| 线程池 timeout | 限制等待结果，不终止已运行线程。上下文管理器退出还可能等待任务完成。需要强终止时使用独立进程和进程组治理，并处理部分副作用；进程也不自动构成沙箱。[Python 官方文档](https://docs.python.org/3/library/concurrent.futures.html) |
| reload 清空模块缓存 | 不会撤回已运行任务、导入副作用或旧引用。真正热更新需版本固定、在途请求隔离与迁移策略；这里不引入动态模块缓存 |
| 异常捕获 + traceback | 捕获可统一错误，不能隔离崩溃/资源耗尽/数据破坏；日志默认不向用户输出堆栈或秘密 |

“内部可信技能”可以降低隔离成本，但不能把声明、入口白名单或线程超时宣传为安全边界。

## 选定架构与替代方案

**选择：文件优先、证据约束、渐进检索、分阶段演化。** 源快照 → 原子断言和来源摘要 → 实体/概念/综合/模式 → 经验证的技能候选。schema 约定横跨各层；来源是数据，不能进入控制层。Agent 做语义工作，脚本做机械检查和可恢复存储。

相比“纯 Markdown + 无工具”，多一点代码换来 hash、血缘登记、链接检查、版本冲突和恢复。相比“向量 + 图 + 常驻引擎全量建设”，保持零服务启动成本、可备份和可检查；代价是没有开箱即用的语义召回、大规模索引或团队治理。这一选择符合当前空仓库、个人本地 skill 的信息；用户规模/权限要求变化时应重新评估。

本方案采用分类状态和证据说明，不默认填 0.85 一类没有校准的“概率”；来源独立性、直接性、权威性、范围、时间与反证分开看。时间衰减只用于复核/检索优先级，访问频率只反映需求。新证据可能取代旧断言，但不因到达更晚而自动胜出。

后续从本机 Hermes llm-wiki v2.1.0 的使用设计吸收了：有界会话恢复、按类型组织的摘要目录、允许标签表，以及 WIKI_PATH 配置；均重新实现为可验证的本地操作。没有采纳固定外链数、较新来源自动胜出或默认把查询变成知识写入的规则。

检索先用目录 + BM25/精确词 + 中文 bigram + agent 手动别名/链路扩展；语义误召回有实测后再增加 embedding，多跳缺口有实测后再增加图，融合可评估 RRF。当前代码没有实现向量/RRF/图数据库，references 中的扩展路径不冒充交付能力。

## 验收与后续优化

交付门槛是工具真实文件测试、skill 格式校验、独立应用 smoke test 和研究结论可追溯。测试记录位于仓库 docs/verification.md。用户实际 gold queries、检索消融、长周期维护成本、跨模型迁移与大规模并发仍待评测；没有这些数据就不能宣称生产认证或最优召回配置。
