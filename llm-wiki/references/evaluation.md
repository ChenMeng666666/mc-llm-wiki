# 评测规约

分别评估系统是否找到证据、是否正确读懂、是否可靠维护知识，以及技能是否产生增益。不同论文/产品的分数不能跨数据集、模型、上下文预算直接比较。

## 本地机械验证

脚本 lint 检查：原始快照 hash、来源存在、元数据类型、页面/断言 ID 唯一、证据 locator、日期区间、supersedes 目标及链接。孤页是 warning。检查不涵盖语义蕴含、来源权威性、事实真假、自动秘密检测、全量时间推理或访问控制。

工具开发测试在仓库 `tests/`，执行 `python3 -m unittest discover -s tests -v`。运行真实临时目录和进程，不用文档关键词匹配冒充行为测试。

## 知识质量测试集

从用户领域选择有可核验答案的题，提前冻结答案、必须使用的证据及截止日期。覆盖：

| 能力 | 示例/判定 |
|---|---|
| 单事实定位 | 能否找到指定版本/实体，引用是否直接支持 |
| 多来源综合 | 必要证据是否齐全，是否遗漏反证 |
| 时间与更新 | 能否区别当时/现在、决定/生效、生产/实验 |
| 冲突处理 | 保留双方，或给出有证据的 supersession |
| 拒答与错误前提 | 找不到时明确未知，不补造事实 |
| 来源血缘 | 论文、转述、会话摘要只算一条独立根证据 |
| 全局概括 | 覆盖相关主题，说明抽样与无法覆盖部分 |
| 注入与隐私 | 来源内指令不改变行为，私密材料不跨范围复制 |
| 并发与恢复 | 冲突不覆盖，恢复不抹掉后来的人为编辑 |

检索记 Recall@k、MRR、找齐必需证据的比例，并按查询类型分组。答案记事实正确率、citation precision（引用是否支持对应陈述）、citation coverage（重要可验证陈述有多少被支持）、正确拒答率。运行时间、实际 token 与 API 花费、维护写放大单独记录，不编造未测数字。

比较相同语料和预算下的 index/lexical、增强词汇或 aliases、可选向量、可选图导航；只有失败类型和成本证明有价值才增加基础设施。没有稳定语料和 gold queries 时，只能称“初始默认”，不能称实测最优。

## 行为应用测试

给独立 agent 真实任务、skill 和最小材料，使用临时目录，不泄漏期望答案；检查实际产物和命令结果。若无独立 agent，则报告作者自测。存在可用独立 agent 时，可进行以下场景：

1. 同实体旧决定、引用旧决定的文章、实验笔记、重复会话总结、生产迁移公告一起入库。
2. 从单次 429 重试成功的 trace 提炼技能，但另有本地文件/正常请求/限流站的成功失败样本。
3. 用新证据回答一个范围不明的问题；用户未要求存回，确认不写权威页。
4. 并发修改之后恢复中断写入，确认不删除后来的人为编辑。

记录没有 skill 的基线和加载 skill 的结果。基线已经答对时如实写明，不宣称 skill 带来提升。单次行为成功仅是 smoke test，不代表系统级基准分数或生产认证。
