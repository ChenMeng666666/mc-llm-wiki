# 浏览与可读性

用 Markdown 编辑器或 Obsidian 打开整个知识根目录，便于同时浏览 wiki 页面和相对路径指向的原始材料。优先从 wiki/index.md 的分类与一句话摘要进入主题，再沿有证据的关联阅读。

页面按需要组织：来源页写结论、方法和局限；实体页写状态、历史和关系；概念页写定义、适用范围和争议；综合页明确问题、比较维度、证据和缺口。保持短段落，真实关联才加链接；不要求固定阅读秒数、行数或两个外链。

使用 [[page-id]] 导航时保持 ID 唯一；希望编辑器直接识别链接时优先使用与文件名一致的 ID，或使用相对 Markdown 链接。CLI 能解析稳定 ID，不代表每个编辑器都能把自定义 ID 自动映射到文件名。

有展示图片时按需在知识根另建 assets/，在 wiki 页面使用相对 Markdown 图片链接，例如 `![示意图](../../assets/diagram.png)`。原始图片若作为证据需另外登记快照。CLI 不支持编辑器专用的嵌入/查询语法验证，不要为展示插件改写 raw。

summary 提供导航，不是证据。标签从允许列表选取；建议用少量领域词，并在 schema.md 解释含义，避免同义拼写形成平行分类。归档优先保留稳定路径和 archived 状态，让历史引用仍可访问。

额外插件、云同步和常驻服务均不在默认流程内；需要时按用户请求单独配置并核验兼容性。多个 agent 或编辑器共同写入时，直接保存文件会绕过 CLI 的协作锁和版本检查，应优先通过统一写入入口提交。嵌套 JSON frontmatter 在具体编辑器/插件中的展示效果需要实际检查。
